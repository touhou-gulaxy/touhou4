# Stellaris 4.6 迁移工作汇总

## 基线

- 当前客户端：`Cygnus v4.5.4`
- 4.6 preview：`Corona Borealis v4.6.0`
- 当前分支：`dev/4.6`
- 当前发布声明仍是 `supported_version="v4.5.*"`
- 相关技能：`.agent/skills/triggered-modifier/SKILL.md`

4.6-only 内容不能直接放进仍需支持 4.5 的发布分支。先拆分版本边界，再按以下顺序迁移。

## P0：版本边界与明确格式变化

### 1. 分离 4.5 发布分支与 4.6 分支

- `descriptor.mod` 当前仍声明 4.5。
- `dev/4.6` 已包含 4.6-only game rules，如 `can_open_ideologies_tab`、`can_cultural_envoy_convert_colony` 和 `ruler_can_*`。
- 4.5.4 已对这些规则产生 `unexpected game rule` 错误。
- Lunar Capital crisis 中已有变量名包含目标的写法；4.5.4 会将其解析为损坏事件目标，4.6 才正式支持。

处理要求：

- 4.5 发布分支保持旧语法。
- 4.6 分支完成迁移和验证后再更新 `supported_version`。
- 不要把 4.6-only 语法和 4.5 发布内容混在同一发布提交。

### 2. 迁移 zone 建筑允许列表

4.6 将 zone 定义中的：

```text
include = { ... }
exclude = { ... }
```

改为：

```text
included_buildings = { ... }
excluded_buildings = { ... }
```

当前有效目标约 16 处，涉及：

- `common/zones/!!!spth_zones.txt`
- `common/zones/!!spth_ag_zones.txt`
- `common/inline_scripts/zones/` 中的实际 zone 模板

不要修改 `*_zone_slots.txt` 或 `common/zone_slots/` 中的 `include`。那是“该槽位可放哪些 zone”，4.6 仍沿用该语法。

### 3. 绝对伦理兼容

当前有 36 处直接检查 `has_ethic = ethic_fanatic_*`。4.6 的 `ethic_absolute_*` 不会自动匹配这些精确检查。

优先处理：

- `events/02_th_events.txt`
- `common/governments/th_governments.txt`
- `common/ascension_perks/`
- `common/policies/`
- 协议条款、舆论修正和自由职业者数值

迁移规则：

- “狂热及以上”使用 `is_fanatic_<ethic> = yes`。
- “普通及以上”使用 `is_<ethic> = yes`。
- 只有必须区分狂热与绝对等级时才显式写两个分支。

### 4. 变量名中的目标

4.6 支持类似 `variable@from` 的变量名；4.5 不支持。

已产生 4.5 错误的位置：

- `events/lunar_capital_psi_crisis_events.txt`
- `common/scripted_effects/touhou_crisis_intelligent_adv_actions.txt`

这些写法只能存在于 4.6 分支。4.5 发布版必须换回固定变量名、按国家拆名或改变状态保存方式。

## P1：需要迁移与实机回归

### 5. Triggered modifier 灰显迁移

使用 `.agent/skills/triggered-modifier/SKILL.md` 的规则实施。

#### 5.1 当前灰色 dummy 统计

- 25 个 `*_dummy_grey` scripted modifier 定义
- 54 处使用
- 分布在 13 个 triggered modifier 块
- 集中在 `leader_trait_matara_1`、`leader_trait_matara_2`、`leader_trait_lilywhite_1`

#### 5.2 直接迁移

`leader_trait_matara_1`：

- `common/traits/touhou_special_leader.txt` 的 planet/sector commander dummy 块
- 保留 real official 块，添加：

```text
show_if_trigger_false = yes
trigger_false_key_override = <requires_official_leader>
```

- 删除 commander dummy 块。

`leader_trait_matara_2`：

- official 管理效果与 commander 军事效果均保留真实块。
- 两个真实 `triggered_councilor_modifier` 都添加灰显和失败条件说明。
- 删除两个 dummy 块。

`leader_trait_lilywhite_1`：

- 四个季节各有 planet 与 sector 块。
- 每个块只保留该季节的真实 modifier。
- 每个块添加 `show_if_trigger_false = yes`。
- 使用 `trigger_false_key_override` 解释“仅在春季/夏季/秋季/冬季生效”。
- 删除每个块内另外三个季节的 dummy modifier。

示例：

```text
triggered_planet_modifier = {
    potential = { spth_is_spring = yes }

    custom_tooltip = leader_trait_lilywhite_1_spring
    show_only_custom_tooltip = no

    show_if_trigger_false = yes
    trigger_false_key_override = leader_trait_lilywhite_1_spring_inactive

    pop_spth_freelancer_bonus_workforce_mult = 0.25
}
```

#### 5.3 暂不迁移

`leader_trait_matara_1` 的 self modifier 使用：

```text
fleet_th_has_matara_dummy_grey = 1
```

真实效果通过 fleet scope 的 `fleet_th_has_matara` 提供。当前没有 4.6 原版证据证明
`triggered_fleet_modifier` 支持相同的 trigger-detail tooltip。首轮保留该 dummy。

#### 5.4 迁移后清理

完成上述直接迁移后可以去除：

- 53/54 处 dummy 使用
- 24/25 个 dummy modifier 定义
- 对应的 24 组 `_dummy_grey` 本地化

清理前确认没有其他引用：

```bash
rg -n '_dummy_grey\\s*=' common
```

预计仅保留 `fleet_th_has_matara_dummy_grey`。

#### 5.5 值得改为不满足时灰显的非 dummy 块

高价值：

- `leader_trait_lilywhite`：春季与反春季效果互补。
- `leader_trait_mystia`：官员岗位与指挥官岗位效果。
- `leader_trait_dream_master`：官员人口效果与指挥官陆军效果。
- `leader_trait_touhou_keiki`：官员自动化人口与指挥官岗位。
- `leader_trait_touhou_seige`：官员统治者产出与指挥官防御。
- `leader_trait_mystia_2`：职业专属的多组独立效果。

中价值：

- `leader_trait_aki_minoriko`：非秋季时灰显秋季加成。
- `common/traits/spth_ag_traits.txt`：
  - `th_ag_interaction_trait_Aurora_gov`
  - `th_ag_interaction_trait_Illustelia_sci`
  - `th_ag_interaction_trait_starlightII_sci`

不建议转换：

- `leader_trait_dream_soul` 的五个统治者分支：tooltip 过长。
- Reimu/Remilia/Sanae/Satori/Yuyuko 等“初始统治者 vs 普通领袖”分支：重复内容过多。
- `leader_trait_touhou_psionic` 的六种身份分支：应使用摘要式 tooltip。
- `spth_councilors.txt` 中 `spth_has_ag_mod` 条件：兼容性实现细节。
- `spth_auto_clear_negative_traits`：内部维护逻辑。
- `trait_touhou` 的 pop-group 基础与灵能分支：pop tooltip 已过载，保持隐藏。

重点回归：

- `events/01_th_game_start.txt`

- `common/scripted_effects/spth_system_spawner.txt`

- 月都、神隐、神社、初始工厂与研究建筑是否正确
- AI 初始殖民地是否与玩家规则一致

### 7. 整事件覆盖

- `shroud.5310`

当前状态：

- `first_contact_critters.25` 已补五个绝对伦理文本分支。
- `shroud.5310` 已补 Open Stars 奖励，但仍保留完整旧 UI。

待办：

- 评估 `shroud.5310` 改用 `base = enclave.405`、`desc_clear`、`option_clear`。
- 保留龙神 patron 选项并在新 base 上重新声明。
- 每次更新重新比较全部 21 个共享事件 ID。

### 9. 领袖背景、统治者兼任与人口控制

- 实测特殊领袖背景、复活领袖和随机领袖池。
- 验证 4.6 的 `ruler_can_*` 规则是否允许东方特殊统治者兼任预期岗位。
- 回归 `planet_population_control` 与 growth/assembly 规则的交互。
- 回归东方初始封锁殖民地、解除控制效果和 AI 殖民地。

### 10. 星港模块

Mod 自定义 `shipyard` 仍使用：

```text
solar_system = { ... }
```

4.6 原版改为：

```text
solar_system? = { ... }
```

合并该变化，避免特殊或无星系统港下的判断错误。

### 11. GUI 与本地化

- 4.6 preview 有 56 个原版 interface 文本文件变化。
- Mod 的 75 个 interface 文件与原版没有同名路径冲突。
- 仍需回归自定义事件窗口、领袖 UI、舰船菜单、行星 UI、议会/对话 UI 和 tooltip。
- 新增 `show_*`、trigger override 和 `fix_key` 时同步所有语言，至少先完成 English 与 Simplified Chinese。

## P2：后续可选优化

- 使用 4.6 megastructure modules 简化太空神社、神隐之心等功能组合。
- 使用 `triggered_buildings` 替代部分多 zone 复制。
- 使用 `clear_variables` 清理分布式危机变量。
- 使用 `remove_system` 简化危机星系删除。
- 使用 `has_faction_with_ethic`、`leader_species_weight_mult`、`leader_lifespan_min` 等新接口。

这些不是 4.6 启动兼容的阻断项。

## 推荐实施顺序

1. 拆分 4.5 发布分支与 4.6 开发分支。
2. 迁移 16 处 zone `include`。
3. 处理 36 处绝对伦理判断。
4. 完成 `triggered-modifier` 灰显迁移。
5. 回归 `add_building` 的开局与初始星系。
6. 处理 `shroud.5310`、共享事件和 30 个 on_action。
7. 回归领袖、人口控制和星港模块。
8. 实测全部自定义 GUI。
9. 更新 `supported_version` 和发布说明。

## 验证清单

- CWTools 对目标 4.6 文件无新增错误。
- 游戏使用 4.6 成功加载。
- `error.log` 无新增 invalid scope、unknown field、missing loc 或 duplicate event。
- 4.5 发布分支仍可独立加载。
- 主动触发所有迁移后的 active/inactive tooltip。
- 灰显行实际不应用效果。
- 删除 dummy 后无悬空 modifier 或本地化引用。
- 不把静态解析成功等同于实机 UI 和游戏语义正确。
